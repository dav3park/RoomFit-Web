# 추천 가능 안내·원룸 가구 구성 개선 — 2026-10-18

커밋·push·배포 없이 로컬 구현과 검증을 완료했습니다. 앞서 진행한 로딩 성능 개선 변경도 보존했습니다.

## 문제와 변경

- 조건 확인은 배치 성공을 보장하지 않습니다. 확인 단계는 “조건 확인이 완료됐습니다. 배치 가능 여부는 추천 생성 시 확인합니다.”로 안내합니다. 실패 시 실제 요청에 맞는 수정 방법과 배치를 찾지 못한 가구 종류를 표시합니다.
- 사진 조건 실패를 5.8×5.4m 원룸에서 재현했습니다. 모서리에 가까운 창문에 커튼 양쪽 여분을 고정으로 더해 경계를 넘었으며, 블라인드에도 일반 바닥 가구의 벽 여유를 적용해 유효한 설치를 거절했습니다. 창문 양쪽의 남은 벽 길이에 맞춰 커튼 여분과 중심을 조절하고, 창문 설치형 가구에는 실제 바닥 경계를 사용합니다. Web 추천·직접 편집 검증과 Backend 설치·검증을 일치시켰습니다. 창문보다 많은 커튼 요청은 창문 수와 요청 수를 명시합니다.
- 일반 새 추천의 비미니멀 구성은 방 면적에 따라 7/9/11개를 목표로 합니다. 공간이 부족하면 선택 가구를 생략하며 미니멀과 기존 종류·개수 유지 모드는 기존 규칙을 유지합니다. 창문이 있으면 커튼·블라인드를, 충분한 원룸에서는 수면·생활 공간 사이 파티션을 우선 후보에 넣고 러그·조명·수납 등으로 구성합니다.
- 파티션은 생활 영역 사이의 위치와 방향을 함께 평가하고 통로를 남길 수 있는 후보를 비교합니다. 커튼 설치를 먼저 결정한 뒤 다른 가구를 배치합니다. 선택 장식 가구는 제한된 후보를 탐색해 가구 수 증가에 따른 탐색 폭을 제어합니다. 최종 충돌·경계·개폐·통로 검증은 유지합니다.
- 사용자가 지정한 수량·제외·고정 조건은 우선합니다. 더 풍성한 구성 목표 때문에 조건을 임의로 풀지 않습니다.

## 검증

- Web 전체 **842 통과, opt-in 벤치마크 1개 제외**, lint·production build 통과. Backend 전체 **958 통과**, bootJar 통과. Backend는 로컬 JDK25 override로 실행했으며 저장소 Java21 설정은 변경하지 않았습니다.
- 회귀 검증: 모서리 창문 커튼/블라인드 설치, 실제 경계 이탈 거절, 벽 두 개만 있는 데모의 방 경계, 파티션 방향, 사진의 여섯 가구 수량, 제외 조건, 창문 없는 방, 미니멀, 기존 가구 유지, 창문 수 초과 요청.
- 실제 production 빌드의 Worker와 UI를 별도 로컬 브라우저로 확인했습니다. 동일한 약 31㎡ 원룸의 일반 추천은 기존 `[4,4,4]`개에서 `[11,10,11]`개로 늘었고, 미니멀은 `[4,4,4]`개로 유지됐습니다. 커튼·블라인드와 파티션 설치를 화면으로 확인했습니다.
- 사용자 화면의 사진 해석 조건을 합성 응답으로 재생했습니다. 수정 전 추천 0개, 수정 후 3개이며 모든 안이 침대1·소파1·러그1·커튼/블라인드1·테이블1·무드등1을 지켰습니다. 추가 가구를 포함한 총 개수는 `[11,11,12]`입니다.
- 창문1·커튼2 조건은 0개와 함께 구체적인 설치 수량 안내를 표시했습니다. 조건 확인 문구도 배치 성공을 약속하지 않습니다.
- PC 1440×900 전후 비교와 모바일 390×844 확인: 수평 넘침 없음, JS 실행 오류 0개. Impeccable detector 결과 `[]`. 기존 Three.js 폐기 예정 경고와 허용되는 접근 여유 공간 주의는 남아 있습니다.
