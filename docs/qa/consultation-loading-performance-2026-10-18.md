# 상담·가구 로딩 성능 개선 — 2026-10-18

범위: 추천안 비교 상담은 제외하고, 사진 준비·가구 파일 전송·분석 출력량과 시간 관찰을 개선했습니다. 커밋·push·배포는 하지 않았습니다.

## 변경

- 배포할 때만 모델 JSON의 공백을 제거합니다. 원본 193개 파일과 모든 숫자·치수·부품은 보존합니다. 축소한 내용으로 SHA-256 파일명을 만들어 새 빌드의 캐시가 이전 내용과 섞이지 않게 합니다.
- 페이지와 추천 Worker가 같은 축소 자산을 사용합니다. 빌드 fixture는 중복 JSON 출력 여부, 변경 시 파일명 갱신, 실제 Worker 실행까지 확인합니다.
- 모델을 처음 받을 때 기본 HTTP 캐시 정책을 따릅니다. 오류 후 재시도는 `reload`로 캐시를 우회합니다. 새 캐시 서버 설정은 추가하지 않았으므로 재방문 효과는 서버 헤더에 따릅니다.
- 사진은 최대 3장을 병렬 준비하며 첨부 순서를 보존합니다. 성공한 JPEG만 File 키의 WeakMap에 보관해 같은 첨부의 재분석에서 재사용합니다. 브라우저 저장소나 서버에 새로 저장하지 않습니다. 취소·실패 검증과 기존 해상도/용량 제한은 유지합니다.
- Backend는 기존 응답 schema와 검증을 유지하면서 간결한 JSON·문구를 요청합니다. [OpenAI 공식 지연 최적화 지침](https://developers.openai.com/api/docs/guides/latency-optimization)의 출력량 절감 방향을 참고했으며, 모델·이미지 상세도·최대 출력 토큰·재시도 예산은 변경하지 않았습니다.
- 분석 성공/실패 시 준비·공급자·검증·전체 소요 시간, 요청 횟수와 출력 글자 수만 기록합니다. 설명·사진·가구 이름·생성 응답은 기록하지 않습니다.

## 측정·검증

- 193개 원본/빌드 JSON을 파싱해 전체 값의 동등성을 확인했습니다. 합계 25,648,907 → 13,252,562 bytes, **48.33% 감소**.
- 가장 큰 C098: 8,189,755 → 4,192,859 bytes. 브라우저에서 10Mbps, 지연 50ms, 캐시 비활성화, 압축 없음으로 번갈아 각 3회 측정했습니다. 다운로드+JSON 파싱 중앙값은 약 **6.64 → 3.43초**입니다. GPU 렌더링·AI 시간은 포함하지 않습니다. 운영 서버 압축 여부에 따라 실제 전송 절감률은 다릅니다.
- 사진 3장으로 두 번 분석하는 실제 UI를 기존 응답으로 재생했습니다. 요청당 사진은 양쪽 모두 3장, JPEG 변환 누적 횟수는 기존 `[3,6]`, 변경 후 `[3,3]`입니다. 신규 외부 분석 요청은 0회입니다.
- 기존 실제 응답을 최종 빌드에서 재생해 Worker 추천 3개를 확인했습니다. 세 안 모두 화분3·책상1·책장1·옷장0이며, 적용·저장하지 않았습니다.
- PC 1440×900와 모바일 390×844에서 전후 화면을 비교했습니다. 대표 mesh/plant 모델 3개 모두 실제 픽셀이 렌더링됐고, 모델 경고 UI·JS 실행 오류는 0개였습니다. 모바일 수평 넘침 없음, Tab으로 첨부 버튼에 포커스 이동 확인. 기존 Three.js 폐기 예정 경고는 남아 있습니다.
- Web 전체: `npm run test:run -- --maxWorkers=2` — **833 통과, opt-in 벤치마크 1개 제외**. `npm run lint`, `npm run build` 통과. 첫 기본 병렬 실행에서 기존 `consultationAudit.test.ts`의 5초 제한을 넘겼으나 단독 및 전체 maxWorkers=2 실행은 통과했습니다. 테스트 시간 제한은 늘리지 않았습니다.
- Backend 전체: `./gradlew -I /tmp/roomfit-deploy-java25.gradle test bootJar` — **955 통과, 실패/오류/제외 0**. 이전 989 집계는 남아 있던 과거 XML 보고서를 포함한 값이어서 정정했습니다. 로컬 JDK25 override만 사용했고 저장소의 Java21 설정은 유지했습니다.
